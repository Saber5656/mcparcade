# Title

Determinism and replay-invariant suite across all games

## Summary

Implement `test/determinism/` per DESIGN.md §8/§19.1: the cross-game suite proving `replay(seed, options, actionLog) ≡ recorded states/events` for every bundled game, including restart-resume equivalence and cross-platform stability in CI.

## Context

Determinism is the load-bearing wall under replays, ratings, and the spectator's frame recompute (ADR-004). Individual games test their own goldens; this suite makes the invariant a single always-on contract and catches cross-cutting regressions (rng draw-order changes, runtime refactors).

## Scope

- Golden corpus, generated by a committed recorder script `tools/record-goldens.ts` (plays the golden transcripts through the harness and hashes canonical-JSON states). Fixture schema (normative): `{gameId, gameVersion, seed, options, actionLog: [{t, playerId, action}] (the session's actionLog with `at` timestamps stripped), finalStateHash, eventLogHash}`. Hash inputs: `finalStateHash` = canonical hash (issue 32's `core/canonical.ts`) of the final `stateSnapshot` verbatim (plugin purity guarantees it contains no ids/timestamps); `eventLogHash` = canonical hash of the full `eventLog` (events carry no wall-clock fields).
- Corpus contents (one fixture each): maze, g2048, sudoku, shogi easy, shogi normal, escape `intro-cell`, escape `locked-lab`, werewolf-A (7p, `agentRole:"random"`, agent survives to a village win), werewolf-B (5p, seed searched once and frozen so the agent dies night 2 — exercises the §15.5b auto-playout).
- Invariant tests: (1) full replay hash equality; (2) `replayToTurn` spot-checks at t ∈ {0, mid, last}; (3) restart-resume: split each fixture at 3 cut points, resume via fresh Runtime (rngCursors path), final hash equal; (4) double-run: two fresh replays in-process are identical.
- Canonical JSON hasher: stable key ordering, no timestamps/ids included (strip list documented — reuse harness normalizers).
- CI wiring: suite runs in the existing matrix (ubuntu+macos × Node 20/22); the *same hashes* must pass everywhere (that's the point).

## Detailed Requirements

1. Hashing: sha256 over canonical JSON via the shared `src/core/canonical.ts` (issue 32; recursively sorted keys, arrays in order) — no second canonicalizer.
2. Fixtures are committed (small: action logs + hashes only); regenerating requires running the recorder and reviewing the diff (guard: recorder refuses to overwrite unless `--force`, keeping accidental regeneration out of PRs).
3. Version coupling: each fixture records `gameVersion`; the suite fails on mismatch with a message telling the implementer to consciously regenerate that game's fixtures (the designed friction from ADR-004). This gate itself is CI-tested: a committed test builds an in-memory copy of a fixture with a mutated `gameVersion` and asserts the suite's version-gate rejection message (no monkeypatching of real games needed).
4. Suite runtime budget ≤ 120 s in CI (shogi normal fixture kept short — ≤ 40 plies scripted).
5. Failure output contract: on hash mismatch the vitest assertion message contains `first divergence at t=<N>` (found by binary search via `replayToTurn` + per-turn canonical hash) plus the expected/actual hashes, and the two diverging turn-state canonical JSONs are written to the test temp dir with their paths printed to stderr (local artifacts; hidden-info content is acceptable in a local test dir).

## Acceptance Criteria

- [ ] All 9 fixtures replay hash-identical on all 4 CI matrix cells.
- [ ] Restart-resume equivalence green for all fixtures at 3 cut points each.
- [ ] Tampering test: mutating one action in an in-memory copy of a fixture fails with the `first divergence at t=` report (self-test of the debug output).
- [ ] Version-gate test (requirement 3) green.
- [ ] Recorder script regenerates byte-identical fixtures when nothing changed.

## Validation

- `npm test -- test/determinism` in CI matrix; recorder run documented in the PR.
